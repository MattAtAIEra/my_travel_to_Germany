期末作業

做一集（或一季）會說話的互動語言教材

用課程手冊學到的流程，為一群真實的學習者做一集互動教材：有角色、有分支劇情、有測驗、有 AI 插圖與配音、有 Suno 背景音樂，放上 Netlify，並且收回真的學習成果。可以一個人做，也可以幾個人一組，或全班一起做成一整季。

1要交什麼

作品

一個上線的網站

Netlify 網址，手機也能玩。裡面至少有你們做的一集。

原始檔

一個 GitHub repo

題庫檔、素材、README（含 AI 使用聲明）。repo 裡不可以有 API 金鑰。

證據與反思

學習成果＋改版

Netlify Forms 收到的學習成果（至少 10 筆）、你們根據資料改了什麼、300 字反思。

2三種組隊方式（自己選）

三種方式的評分標準一樣，差別在「份量」與「協作」。不論哪一種，每個人都要親手操作過工作台（產生過語音或圖片）。

單人一組

做一集精簡版

  • 2–3 個角色（可以直接沿用範例角色）
  • 2 個劇情選擇＋1 個測驗
  • 長度 1.5–3 分鐘
  • 回顧＋單字卡

適合想完整走一次流程、時間比較少的人。

小組（2–5 人）

做一集完整版

  • 自己設計的角色（不沿用範例）
  • 3 個選擇點，其中至少 1 個測驗
  • 3–5 人的組：再加第二集，或加一個「華語／英語」雙語版本
  • 依下方「小組分工」分配角色
全班共同建構

一起做一整季

  • 全班共用同一個世界觀、同一組角色、同一個網站
  • 每組（或每人）負責一集
  • 要遵守全班一起訂的「系列規格書」
  • 學到真實團隊開發的協作與整合

做法見第 5 節。

3小組分工

一個人可以兼好幾個角色；人少的組，製作人通常也是題庫工程師。每個角色都有一份「交出去的東西」，這是互評的依據。

角色負責交出去的東西對應課程
製作人時程、分工、對外溝通、最後決定企劃單、每週進度表、發表第 1、11 課
編劇故事、角色個性、台詞流程圖、完整台詞第 2、3 課
互動設計師選擇點、測驗、回饋台詞題目與選項表，符合五條規則第 4 課
題庫工程師把腳本整理成題庫檔，維持零錯誤content/ 裡的題庫檔、上線第 5、10 課
美術導演畫風句、角色外型、每一張圖的檢查角色設定圖、所有插圖第 6 課
聲音導演選聲音、語氣說明、背景音樂所有語音、BGM 與音量設定第 7、8 課
測試員三輪測試、找人試玩、回報問題測試紀錄、問題清單（含修好了沒）第 9 課
協作小技巧
題庫檔一次只讓一個人改（通常是題庫工程師），其他人把修改意見寫在共用文件或 GitHub 的 Issues 裡。兩個人同時改同一個檔案，最後一定有人的修改被蓋掉。

4題材清單

每個題材都已經幫你配好一個「一集只教一件事」的學習目標。可以照用，也可以改；自由提案請先給老師看企劃單。

A. 兒童英語（6–10 歲；可以延續 Captain A 系列）

題材這一集只教測驗題可以怎麼出
Rex 的生日派對How old are you? / I'm seven.Rex 七歲，他該怎麼回答？
顏色水果攤形容詞放在名詞前面：a red appleFunky 要買紅色的蘋果，怎麼說？（apple red / a red apple / red a apple）
動物園a 和 an：an elephant、a tigerFunky 看到大象，該說 a 還是 an？
今天天氣It's sunny / rainy / windy.窗外在下雨，Rex 該怎麼說？
我的心情I'm happy / sad / tired.Funky 打了一個大哈欠，她覺得怎樣？
早餐吃什麼I like… / I don't like…Captain A 不喜歡牛奶，他怎麼說？
穿衣服出門put on：Put on your coat.外面很冷，Funky 要提醒 Rex 做什麼？
數到十數字＋複數 s（延伸 KK01）桌上有三顆球，怎麼說？

B. 晨間英語（上班族、大學生；延續 Morning English 系列）

題材這一集只教三個選擇點的走向
咖啡店點餐Can I get…? 比 I want… 有禮貌點餐 → 客製化 → 付款時的小聊天
視訊會議遲到道歉要短，接著馬上回到正事進會議的第一句 → 被問問題 → 會後補救
請同事幫忙Would you mind…? / Could you…?開口 → 說明原因 → 道謝與回報
婉拒加班I'd love to, but…（先肯定再拒絕）被問 → 拒絕 → 提出替代方案
三十秒自我介紹名字 → 做什麼 → 一個讓人記得的細節開場 → 重點 → 收尾
面試第一題Tell me about yourself. 的三段式現在 → 過去 → 為什麼是這裡
打電話請病假說明、交代、約定回覆時間開口 → 交代工作 → 結束通話

C. 華語教材（給外籍學習者；配音用台灣口音的國語）

題庫的 lang 和角色的 lang 都寫 "zh-TW"，按鈕文字 ui 可以用 "en"（讓剛開始學中文的人看得懂）。字幕下的 hint 可以放漢語拼音或英文翻譯。

題材這一集只教測驗題可以怎麼出
夜市點餐量詞：一份雞排、一杯奶茶、一碗麵線要一碗蚵仔麵線，怎麼說？
手搖飲客製化甜度與冰塊：半糖、少冰、去冰想要一半的甜度，該說什麼？
搭捷運往……方向、在……站下車要去台北 101，在哪一站下車？
便利商店聽懂店員的問題：要袋子嗎？要加熱嗎？店員問「需要袋子嗎？」，不需要怎麼回？
看醫生描述哪裡不舒服：我頭痛、我喉嚨痛喉嚨痛，該怎麼跟醫生說？
「了」的用法動作完成：我吃了。／我吃飯了。朋友問「你吃飯了嗎？」，吃過了怎麼回答？
中秋節烤肉邀請：要不要一起……？想約朋友一起烤肉，怎麼開口？
華語配音注意
破音字（行、長、重、還、了）一定要逐句聽過。念錯時換一個說法，或在那一句的 style 裡註明讀音。

D. 旅行英語（呼應這個網站的德國旅行主題）

題材這一集只教
機場報到Window or aisle? / Is my bag overweight?
火車誤點要改票My train was cancelled. Can I take the next one?
飯店入住I have a reservation under…
餐廳點餐與飲食需求I'm vegetarian. / Does this have nuts?
東西掉了I lost my… Where is the lost and found?

E. 自由提案

台語、客語入門（語音品質請先試聽確認）、手語詞彙配圖、給長輩的手機英文、給新住民的華語……都歡迎。先交企劃單給老師確認。

5全班共同建構一季：怎麼做

全班共用一個引擎、一個網站，每組各寫一集。這就是真實團隊開發的樣子：大家各自工作，最後要能「接得起來」。能不能接得起來，靠的是事先講好的規格。

步驟 1

一起訂「系列規格書」（第一週，全班）

  • 世界觀與角色：全班共用的角色，整段 cast（名字、emoji、顏色、聲音、語氣、外型）定稿後每一集都照抄，不准改。
  • 畫風句 art.style、語音要求 speech.note、主題色 theme：全季一樣。
  • 集代號規則：每組有自己的代號開頭，避免撞名，例如第 3 組用 s1e03。素材資料夾也就不會撞在一起。
  • 骨架：要不要固定「暖場 → 選擇 ×2 → 測驗 → 結局 → 回顧 → 單字卡」、長度多少。
步驟 2

各組在自己的 starter kit 裡開發

每組照課程手冊做自己的那一集，只動自己的題庫檔和自己的素材資料夾。角色設定圖由「美術組」或老師統一產生一次，發給各組放進自己的素材資料夾，確保長相一致。

步驟 3

交給整合人，放進全班的網站

每組交出兩樣東西：content/s1e03-xxx.js 和 assets/s1e03/ 整個資料夾。整合人（老師、助教或選出來的「總編輯」）把它們放進全班的 repo，在 content/episodes.js 加上一行，打開工作台確認零錯誤，再上傳。全班的網站目錄上就多了一集。

進階做法：整合人在 GitHub 把各組加為協作者（Settings → Collaborators），各組直接上傳自己的檔案。

工程師的說法
系列規格書就是團隊之間的介面約定：只要每一組交出來的東西符合約定，整合人不必看懂每一集的內容也接得起來。工作台的「檢查題庫」就是整合前的驗收測試。

週上課內容這一週結束要交
1第 0、1 課：先讓它跑起來、企劃M1 企劃單（組隊方式、分工、題材）
2第 2、3 課：角色、腳本M2 角色卡＋流程圖
3第 4 課：互動題目設計M3 完整台詞與題目（同學互看一次）
4第 5 課：題庫檔M4 可玩版：題庫零錯誤，用電腦語音可以從頭玩到尾
5第 6 課：圖像角色設定圖＋第一張圖給老師看過畫風
6第 7、8 課：聲音、背景音樂M5 素材完成版：所有語音、圖、BGM
7第 9 課：整合與測試測試紀錄（三輪）＋同學互測回報

課程只有 6 週時：第 2–3 週合併、第 5–6 週合併、第 7–8 週合併。兩天工作坊：第一天做到 M4 可玩版，第二天做素材、上線。

8評分規準

面向比重優秀的樣子常見扣分
學習設計25%學習者具體；一集只教一件事；情境是學習者真的會遇到的；「怎樣算成功」有寫、有檢查一集教太多；目標無法驗證
互動與題目20%選擇有意義、各有代價；錯誤選項來自真實的錯；符合五條規則；回饋溫和且說出正解答案寫在題目上；答錯的人聽不到正解；選項一看就知道哪個對
角色與腳本15%角色各有任務與鮮明個性；台詞自然、一句一個念頭；分支都回得來角色只是傳聲筒；主線接不上某條分支
圖像與聲音15%畫風與角色長相一致；沒有亂碼字；語氣到位、華語讀音正確；BGM 不搶戲角色每張長得不一樣；破音字念錯；音樂蓋過人聲
技術完成度15%驗收清單全部通過；手機好用；有測試紀錄上線後缺圖缺聲音；表單收不到
資料與改版10%從學習成果看出問題，做出有根據的第二版；發表說得清楚只有一版；沒有看資料

小組作品：小組分數 × 個人調整（0.8–1.2）。個人調整依據：同儕互評、每個角色「交出去的東西」，以及 GitHub 的修改紀錄。全班共同建構：個人分數看自己那一集，另有 10% 看「有沒有遵守系列規格書、整合時有沒有出問題」。

9AI 使用與誠信

  • 可以：用 Gemini 產生插圖與語音、用 Suno 產生音樂，這是作業的一部分。
  • 要說清楚：腳本與題目如果有請 AI 協助（例如請 AI 給你十個題材點子、幫你檢查英文），在 README 寫出來，並說明你自己改了什麼。
  • 不可以：使用他人的角色（卡通、遊戲、品牌角色）、真人照片或聲音、在描述裡指定在世創作者的風格。
  • 不可以：把 API 金鑰放進作品或分享給別人；收集學習者的真實姓名、學號、聯絡方式。
## AI 使用聲明（範例，放在 README 最後）
- 插圖：Google Gemini（gemini-3.1-flash-image），畫面描述由 ___ 撰寫
- 語音：Google Gemini（gemini-3.8-flash-tts），角色聲音：Captain A＝Puck……
- 背景音樂：Suno，提示詞見 content/ 題庫檔的 bgm.suno
- 腳本：由 ___、___ 撰寫；使用 ___ 協助檢查英文文法，並由 ___ 修改定稿

10怎麼繳交

期末前到 繳交頁 填表（每組一份）：作品網址、GitHub repo 網址、成員與分工、收到幾筆學習成果、第二版改了什麼、反思。繳交後可以再交一次，老師以最後一次為準。

評分時老師會做的事

打開你的網址，用手機玩三輪（每個選項至少選一次）、送出一筆學習成果；打開 GitHub 看題庫檔和 README；用工作台跑一次「檢查題庫」。所以，只要你的作品通過驗收清單，就不會有意外。
