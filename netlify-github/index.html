從零開始，把你的網頁放到網路上
GitHub ＋ Netlify 連動，照著做 23 步

這份手冊給第一次做的人。每一步只做一件事，做完打勾再往下；有幾步畫面比較多，拆成了小步驟（例如 10-1、10-2）。全部做完大約一小時，做完你會有一個全世界都打得開的網址，而且之後改網頁只要在 GitHub 上存檔，網站就會自己更新。

約 1 小時需要：一個 email、一支手機、一台電腦完成後：https://你取的名字.netlify.app

0開始之前：三樣東西、四個名詞、一張圖

一個 email

學校信箱或 Gmail 都可以。待會兩個網站都會寄驗證信給你，請用你現在就能打開的信箱。

一支手機

兩階段驗證要用。建議先裝好 Google Authenticator（iPhone、Android 都有，免費）；iPhone 也可以用內建的「密碼」app。

一台電腦

用 Chrome、Edge 或 Safari。手機也能做，但畫面小、容易按錯，建議用電腦。

名詞用一句話說你可以把它想成
GitHub放程式的網站。你的網頁檔案會存在這裡，而且每一次修改都有紀錄。程式的雲端硬碟，但多記了每一次改了什麼。
repo（repository）GitHub 上的一個「專案資料夾」。一個作品一個 repo。雲端硬碟裡的一個資料夾。
Netlify把 GitHub 上的網頁檔案變成一個網址的服務。免費、不用信用卡。幫你把資料夾「掛到網路上」的人。
部署（deploy）Netlify 從 GitHub 拿你最新的檔案，更新到網址上。按下「發布」。
兩階段驗證（2FA）登入時除了密碼，還要輸入手機上的 6 位數。GitHub 規定一定要開。家門除了鑰匙還有一道密碼鎖。

怎麼讀這張圖：實線箭頭是今天要做的事，由左到右；虛線是做完之後每次更新會發生的事。你只需要碰 GitHub，Netlify 會自己動。

1GitHub 帳號與兩階段驗證 約 15 分鐘

GitHub 的註冊會問你 email、密碼、使用者名稱、國家，然後寄一封信確認。兩階段驗證是 GitHub 的規定，第一次設定會花五分鐘，之後每次登入只要多輸入手機上的 6 位數。

步驟 1

打開 GitHub，按右上角的 Sign up

在瀏覽器網址列輸入 github.com，按 Enter。右上角有兩個按鈕，按右邊白底的 Sign up。

你會看到
一個只有一個欄位的頁面，問你的 Email。
卡住了？
看到「Sign in」而不是「Sign up」：那是登入。往右邊找白底的 Sign up。如果整頁變成英文以外的語言，不影響，按鈕位置一樣。
步驟 2

填 email、密碼、使用者名稱

右半邊標題 Sign up for GitHub，所有欄位都在同一頁，由上往下填完，最後按綠色的 Create account。

  1. Email：你現在能打開的信箱。（最上面的 Continue with Google／Apple 也能註冊，但後面驗證信的流程會不一樣，跟著手冊做的話請填 Email。）
  2. Password：欄位下方的灰字寫著規則：至少 15 個字元；或至少 8 個字元並且含數字與小寫字母。建議用一句你記得住的話，例如 wo-ai-tang-shi-2026。
  3. Username：英文字母、數字，中間可以用一個連字號 - 隔開，開頭和結尾不能是連字號，不能有空格。這個名字會出現在你的作品網址裡，所以取一個你願意公開的，例如 ling-reads、poem-lab。不必是真名。
  4. Your Country/Region：選 Taiwan（通常已經自動選好）。
  5. Email preferences：要不要收產品消息，不勾也可以。
你會看到
按下 Create account 之後，會出現一個「證明你不是機器人」的小遊戲（旋轉圖片或拼圖），照指示做完，就會進到下一步輸入驗證碼的畫面。
卡住了？
  • Username 出現紅字：通常是名字被別人用走了，加上年份或喜歡的數字，例如 ling-reads-26。
  • 密碼一直紅字：直接用一句話加連字號，長度夠就會過。
  • 小遊戲一直失敗：重新整理頁面再來一次，或換 Chrome。
步驟 3

到信箱找 8 位數的驗證碼

畫面標題變成 Confirm your email address。GitHub 會寄一封信到你的 email，標題類似 Your GitHub launch code。打開信，裡面有一組 8 位數字，回到 GitHub 的頁面輸入，按 Continue。

卡住了？
  • 等兩分鐘還沒收到：到「垃圾郵件」或「促銷內容」找。
  • 學校信箱有時擋信：按頁面下方的 Resend the code 重寄一次。
  • 發現 email 打錯了：按旁邊的 update your email address 改成正確的信箱。
步驟 4

跳過問卷，選免費方案

GitHub 會問你是學生還是老師、想做什麼。這些都可以按 Skip（通常在頁面下方很小的字）。如果出現方案選擇，選 Free，按 Continue for free。

你會看到
GitHub 的首頁變成登入後的樣子：左邊有一欄「Top repositories」，右上角是你的頭像。恭喜，帳號有了。
步驟 5

找到兩階段驗證的設定頁

按右上角你的頭像 → 選單裡的 Settings → 左邊欄位找 Password and authentication（密碼與驗證）→ 頁面中間有一塊 Two-factor authentication，按綠色的 Enable two-factor authentication。

為什麼
GitHub 從 2023 年起要求所有會上傳程式的帳號開啟兩階段驗證。現在不開，過幾天登入時它會強制你開，到時候手邊沒手機會更麻煩。
卡住了？
找不到 Settings：點頭像後選單很長，Settings 在 Sponsors 底下、Copilot settings 上面。找不到 Password and authentication：它在左欄「Access」那一組底下。
步驟 5-1

同一頁的 Passkeys：之後可以不用打密碼登入

選做

下面這張圖把整條路徑標出來：① 頭像選單的 Settings → ② 左欄的 Password and authentication → ③ Sign in methods 裡的 Passkeys。步驟 5 走的就是 ①、②；③ 是同一頁上方的另一種登入方式。

  1. Passkey 是用手機或電腦本身的解鎖方式（指紋、Face ID、裝置密碼）登入 GitHub，不用打密碼，也不怕被假網站騙走密碼。
  2. 今天先不用設定。等步驟 6～8 把兩階段驗證開好，之後想要更方便登入，再回到這一格新增 passkey。
為什麼
兩階段驗證是「密碼＋手機上的 6 位數」，每次要打兩樣東西；passkey 是一個動作（例如按指紋）同時完成兩件事。課堂上先把兩階段驗證開好，是因為那是 GitHub 規定一定要有的；passkey 是之後加上去的方便選項。
步驟 6

用手機掃 QR code，輸入 6 位數

GitHub 可能先要你再輸入一次密碼，然後進到 Enable two-factor authentication (2FA) 頁，中間一塊 Setup authenticator app，有一個 QR code。頁面上方的 1、2、3 是設定進度，現在在第 1 格。拿出手機：

  1. 建議用 Google Authenticator（iPhone、Android 都有）：打開 app → 右下角「＋」→ 掃描 QR code。GitHub 頁面上舉例的是 1Password、Authy、Microsoft Authenticator，這些也都能用，只是 Google Authenticator 最簡單。
  2. iPhone 不想另外裝 app：打開相機對準 QR code，上面會出現「在密碼中設定驗證碼」，點它，存起來。之後到「密碼」app 就能看到每 30 秒變一次的 6 位數。
  3. 把手機上現在顯示的 6 位數 輸入到電腦上 Verify the code from the app 那一格，按 Continue。
卡住了？
  • 6 位數一直說錯：手機時間要是「自動設定」。到手機的日期與時間設定開啟自動，再試一次新的數字。
  • 手機掃不到 QR code：按 QR code 下面那行的 setup key，會出現一串英文數字，在 app 裡選「輸入設定金鑰」手動打進去。
  • 真的不想用 app：如果畫面上有 SMS 選項，可以改用簡訊，國碼選 Taiwan +886。app 比較穩，簡訊偶爾會慢。
步驟 7

下載救命用的 Recovery codes，存兩個地方

GitHub 會給你一張 Recovery codes（16 組像 abcde-12345 的字）。按 Download 存成檔案，再截圖一張到手機相簿。然後勾選 I have saved my recovery codes，按 Done。

為什麼
手機掉了、換了、重置了，驗證 app 裡的數字就沒了。這時候唯一能進帳號的方法就是這些 recovery codes，每一組只能用一次。存在雲端硬碟（Google Drive、iCloud）加手機相簿，兩個地方。
步驟 8

登出再登入一次，確認兩階段驗證有用

右上角頭像 → 最下面 Sign out。再按 Sign in，輸入帳號密碼，它會多問你一個 6 位數，打開手機的驗證 app 看，輸入。

你會看到
順利回到 GitHub 首頁。到這裡第一部分完成。

2第一個 repo 與第一頁網頁 約 10 分鐘

Netlify 要有東西可以掛，所以先在 GitHub 上建一個資料夾（repo），放進一個最小的網頁檔 index.html。這一段全部在瀏覽器裡做，不用安裝任何東西。

步驟 9

建立一個新的 repo

右上角頭像左邊幾個圖示裡有一個 「＋」，按下去選 New repository。表單分兩段：1 General（名字）和 2 Configuration（設定）。

  1. Owner：你的使用者名稱（預設就是，不用改）。
  2. Repository name：英文小寫、不要空格，例如 my-first-site。打完下面出現綠字 is available 就是可以用。
  3. Choose visibility：右邊選單保持 Public（公開，預設就是）。Netlify 免費方案要公開的 repo 才能連，網頁本來就是要給人看的。
  4. Add README：右邊的開關預設是 Off，按一下切到 On。
  5. 其他（Description、Add .gitignore、Add license）都不用動，按最下面綠色的 Create repository。
你會看到
一個新頁面，網址變成 github.com/你的名字/my-first-site，裡面只有一個 README.md 檔案。這就是你的 repo。
步驟 10

Add file → Create new file，開一個新檔案

在 repo 頁面，找到 Add file 按鈕（綠色 Code 按鈕的左邊），按下去，選單裡選 Create new file（另一個 Upload files 是上傳電腦裡的檔案，今天不用）。

卡住了？
找不到 Add file：視窗太窄時它會縮成一個「＋」圖示，在 Code 按鈕旁邊。
步驟 10-1

取檔名 index.html，貼上一頁最小的網頁

畫面變成一個編輯器，照圖上黃框的 1、2 順序做：

  1. 最上面 repo 名字後面的檔名欄位，輸入 index.html（一個字都不能錯，全部小寫）。
  2. 把下面這段整個複製（按右上角「複製」），貼進中間的大編輯框。「你的名字」那幾個字可以先改成自己的。
  3. 按右上角綠色的 Commit changes…（黃框 2）。
<!DOCTYPE html>
<html lang="zh-Hant">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1">
  <title>我的第一個網頁</title>
  <style>
    body { font-family: "PingFang TC", "Microsoft JhengHei", sans-serif; max-width: 640px; margin: 80px auto; padding: 0 24px; line-height: 1.8; color: #14243A; }
    h1 { font-size: 40px; }
    .seal { display: inline-block; border: 3px solid #C8321F; color: #C8321F; padding: 4px 12px; border-radius: 8px; transform: rotate(-4deg); font-weight: 700; }
  </style>
</head>
<body>
  <p>文學院 AI 服務實作課</p>
  <h1>你的名字 的第一個網頁</h1>
  <p>床前明月光，疑是地上霜。</p>
  <p>這一頁是我自己放上網路的。</p>
  <p class="seal">上線</p>
</body>
</html>
卡住了？
貼上之後縮排亂掉、或第 8、10 行很長被切到畫面外：不影響，網頁一樣能用。只要第一行是 <!DOCTYPE html>、最後一行是 </html> 就對了。
步驟 10-2

跳出 Commit changes 視窗，再按一次 Commit changes

畫面中間跳出一個小視窗，標題 Commit changes（存檔）。

  1. Commit message：這一次存檔的說明。GitHub 的 AI 助手 Copilot 會先幫你填一句英文（例如 Add initial HTML structure for a webpage），可以直接用，也可以改成中文，例如「新增第一頁網頁」。
  2. Extended description（較長的補充說明）留空。
  3. 下面兩個選項保持第一個 Commit directly to the main branch（直接存到主線）。
  4. 按綠色的 Commit changes。

「commit」就是存檔。GitHub 每一次存檔都會留下紀錄，所以叫它 commit 而不是 save；Commit message 就是那一筆紀錄的標題。

為什麼
第二個選項 Create a new branch 是多人一起改同一個專案時用的：先存在另一條分支，別人看過再合併回主線。今天只有你一個人，直接存到 main，Netlify 才會拿到這個檔案。
卡住了？
按 Commit changes 沒反應：小視窗可能被擋在下面，往下捲找綠色按鈕。
步驟 11

確認 repo 裡有兩個檔案

回到 repo 首頁（點上面的 repo 名字），檔案列表應該有 README.md 和 index.html 兩個。點 index.html 可以看到你剛貼的內容。

你會看到
兩個檔案：README.md 旁邊寫著 Initial commit，index.html 旁邊是你在步驟 10-2 留的那句說明。第二部分完成。

3Netlify 帳號與團隊 約 10 分鐘

Netlify 可以直接用剛才的 GitHub 帳號登入，少記一組密碼，之後連動也更順。註冊完它會請你取一個「團隊」（team）名稱，一個人也是一個團隊，隨便取就好。

步驟 12

打開 Netlify 的註冊頁，選「Sign up with GitHub」

在網址列輸入 app.netlify.com/signup（或到 netlify.com 按右上角 Sign up）。在幾個按鈕裡，按 Sign up with GitHub。

為什麼
用 GitHub 登入 Netlify，等一下「連動」那一步 Netlify 就已經認得你的 GitHub，少一次授權。用 email 註冊也可以，只是多一組密碼要記。
步驟 13

GitHub 跳出授權視窗，按 Authorize

畫面會跳到 GitHub，標題寫著 Authorize Netlify Auth，中間 Personal user data 列出 Netlify 想讀取的資料：只有你的 email，而且是唯讀。按下面綠色的 Authorize netlify。如果這時 GitHub 要你輸入密碼或 6 位數，照做。

卡住了？
視窗被瀏覽器擋下來（網址列右邊出現「已封鎖彈出式視窗」）：點那個圖示選「一律允許」，再按一次 Sign up with GitHub。
步驟 14

取團隊名稱，問卷可以跳過

回到 Netlify，它會問幾個問題（你是誰、要做什麼），都可以選最接近的或按 Skip。重要的只有一題：What is the name of your team?。在 Name your team 那一格填自己的名字或班級加年份，例如 ling-2026，按 Continue to deploy。

為什麼
Netlify 把所有專案放在「團隊」底下，就算只有你一個人也要有一個團隊。這堂課每個人一個團隊；之後如果要和同學一起做，再邀請對方進同一個團隊。
步驟 14-1

看到 Page not found 不用慌，按 Back to home

按完 Continue to deploy，畫面可能先跳出一個機器人圖案和大字 Page not found。這不是你做錯，是 Netlify 新手引導換頁時的暫時錯誤，你的帳號和團隊都已經建好了。直接按下面的 Back to home 回首頁。

卡住了？
不要按上面的 Log in with a different user，那是換一個帳號登入，會把你登出。如果你沒有看到這一頁、直接進到首頁，這一步打勾跳過就好。
步驟 15

認識 Netlify 的首頁，找到 Import a Git repository

現在你在 Projects 頁（舊版叫 Sites，就是「專案」）。左上角是你的團隊名稱，左邊一欄有 Projects、Builds、Usage & billing、Team settings。中間標題 Add your project to Netlify，由上到下分三塊：

  1. Start building with an AI agent：打一段描述，讓 AI 幫你寫網站。今天不用，我們的網頁已經放在 GitHub 上了。
  2. Import a Git repository：從 Git 匯入，一排按鈕是 GitHub、GitLab 等程式託管網站。今天用這一塊，黃框圈起來的 GitHub 就是下一步要按的。
  3. Upload your project files：把資料夾拖進來上傳。這樣做也能上線，但之後每次修改都要重新拖一次，不會自動更新，所以今天不用。

先看一下就好，下一部分從按 GitHub 開始。

你會看到
左上角有你的團隊名稱。如果上方出現要你確認 email 的提示條，去信箱點一下 Netlify 寄的確認信。第三部分完成。

4連動 GitHub、建立專案 約 15 分鐘 ‧ 最重要的一段

這一段做的事情是：告訴 Netlify「我的網頁檔案在 GitHub 的那個 repo 裡，請你拿去變成網址，而且以後我每次改，你都自動更新」。中間 GitHub 會跳出兩次視窗要你同意，這是正常的。

步驟 16

按 GitHub，在跳出的視窗按 Authorize

在步驟 15 那一頁的 Import a Git repository，按 GitHub。GitHub 會跳出一個視窗，標題 Netlify by Netlify wants access to your GitHub account，下面列出 Netlify 要做的三件事：

  1. Verify your GitHub identity：確認你的 GitHub 身分。
  2. Know which resources you can access：知道你能存取哪些 repo。
  3. Act on your behalf：代替你去讀 repo、標示部署結果。

按最下面綠色的 Authorize。

為什麼
步驟 13 已經授權過一次，那次的對象是 Netlify Auth，只是讓 Netlify 用 GitHub 認出你是誰。這一次的對象是 Netlify 這個 GitHub App，讓它可以代替你去讀 repo。至於它能讀哪些 repo，下一步（步驟 17）由你決定。
步驟 17

在 GitHub 安裝 Netlify，只開放你剛建的 repo

GitHub 會跳出視窗 Install Netlify。這一步是在 GitHub 這邊「允許 Netlify 讀你的 repo」。

  1. 最上面寫著 Install on your personal account 加上你的使用者名稱，確認是你自己。如果問要裝在哪個帳號，選你自己的使用者名稱。
  2. for these repositories（可以讀哪些 repo）：預設選的是 All repositories（全部），改選 Only select repositories（只開放我選的）。
  3. 選了之後下面會出現 Select repositories 下拉選單，選 my-first-site。
  4. with these permissions 列出 Netlify 會拿到的權限：讀程式碼，以及在 GitHub 上標示每次部署成功或失敗。不用改。
  5. 按最下面綠色的 Install。可能會再要你輸入一次密碼或 6 位數。
為什麼
選「只開放我選的」而不是「全部」，是資訊安全的習慣：一個服務只拿到它需要的東西。之後有新作品要上線，再回來把新的 repo 加進清單就好。
卡住了？
視窗關掉之後 Netlify 沒反應：重新整理 Netlify 頁面，再按一次 GitHub，這次應該直接列出你的 repo。
步驟 18

回到 Netlify，點你的 repo

視窗關閉後回到 Netlify，標題 Let's deploy your project with…，上方進度條走到第 2 格 Select repository。頁面列出 Netlify 可以讀到的 repo，應該只有一個 my-first-site。點那一列。

卡住了？
清單是空的、或沒有你的 repo：按清單下方的 Configure the Netlify app on GitHub，回到步驟 17 的畫面把 repo 加進去。
步驟 19

取專案名稱（也就是你的網址），其他不用填，按 Deploy

進度條走到第 3 格 Configure project and deploy，標題 Review configuration for my-first-site。欄位很多，但純 HTML 的作品只需要動一格：Project name。

  1. 標題下面那行寫著 Deploy as 你的帳號 on 你的團隊 team from main branch，確認最後是 main。Team 選單就是步驟 14 取的團隊，不用改。
  2. Project name：Netlify 會先放一個名字，改成你自己喜歡的英文，單字之間用連字號 - 隔開，例如截圖裡的 my-2026-class。打字時下面會即時顯示 https://my-2026-class.netlify.app，出現綠字 Project name is available 就是可以用。這個名字就是你的網址，取一個願意給別人看的。

往下捲，經過 Build settings（建置設定）一路到最下面：

  1. Build command、Publish directory：留空。
  2. Functions directory：預設是 netlify/functions，不用動（我們沒有那個資料夾，Netlify 會直接略過）。
  3. Environment variables（環境變數）：不用加。
  4. 按最下面的 Deploy 你取的名字（截圖裡是 Deploy my-2026-class）。
為什麼
Build command 是給「要先編譯才能變成網頁」的專案用的。我們的 index.html 本身就是網頁，不用編譯，所以留空。以後用 React 這類工具時才會填。Project name 在這裡先取好，網址一上線就是你要的；如果上線後才改名，舊網址會失效，已經傳出去的連結就打不開了。
卡住了？
Project name 出現紅字（名字被用走了）：加上年份或系所，例如 ling-poem-2026。只能用英文小寫、數字、連字號。
步驟 20

等一分鐘，拿到網址，點開

頁面會顯示 Deploying（部署中）→ Published（已發布）。綠色的 Published 出現後，頁面上方有一行 https://你在步驟 19 取的名字.netlify.app，點它。

你會看到
新分頁打開你在步驟 10-1 貼的那一頁：「你的名字 的第一個網頁」和一枚「上線」印章。它現在在全世界的網路上了。用手機打開同一個網址試試。
卡住了？
  • 打開是 Page not found：檔名不是 index.html（大小寫、多了空格），回 GitHub 改檔名，Netlify 會自動重新部署。
  • 一直停在 Deploying 超過三分鐘：重新整理頁面；還是不行就到左邊 Deploys 點那一筆看紅字。
步驟 21

之後想換網址：找到改專案名稱的地方

步驟 19 已經取好名字的話，這一步看一下位置就好，之後想換網址再回來改。在專案頁面，左邊欄按 Project configuration（舊版叫 Site configuration）→ General → Project details 區塊 → 按 Change project name，輸入新的名字（英文小寫、數字、連字號），按 Save。

你會看到
網址變成 https://新的名字.netlify.app。舊的網址會失效，所以已經把網址給別人的話，要再通知一次。
卡住了？
名字被用走了（紅字 already taken）：加上年份或系所，例如 ling-poem-2026。

5之後怎麼更新 約 5 分鐘

連動完成之後，你再也不用碰 Netlify。只要在 GitHub 上改檔案、存檔，Netlify 大約一分鐘後就把網址更新成新版。試一次你就會相信。

步驟 22

在 GitHub 上改一行字，存檔

回到 GitHub 的 repo，點 index.html，右上角有一支鉛筆圖示（Edit this file），按它。把「床前明月光」那一行改成你喜歡的任何一句話，然後右上角 Commit changes… → 在跳出視窗的 Commit message 寫一句改了什麼（例如「換一句詩」，跟步驟 10-2 是同一個視窗）→ Commit changes。

為什麼
存檔時寫的那一句話，就是 Git 的「紀錄」。三個月後回來看，你會知道每一版改了什麼。寫「改了什麼」，不要寫「update」。
步驟 23

回 Netlify 看它自己更新

回到 Netlify 專案頁，左邊 Deploys。最上面會多一筆新的部署，從 Building 變成 Published，大約一分鐘。然後重新整理你的網址，新的那句話已經在上面了。

你會看到
部署紀錄裡寫著你剛才的說明「換一句詩」。從現在起，改網頁 ＝ 在 GitHub 存檔，其他都是自動的。

你完成了：一個會自己更新的網址

把 https://你取的名字.netlify.app 貼到課堂平臺、傳給三個朋友，看他們打開之後第一眼看到什麼、卡在哪裡。這就是下一堂課的開始。
